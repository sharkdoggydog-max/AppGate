# AppGate 3

Бесплатная открытая программа для блокировки доступа к окнам приложений паролем на Windows. Собственная реализация, не продукт Cisdem и не копия его кода.

## Возможности текущей версии

- Запрос пароля при появлении защищённого окна независимо от способа запуска: Пуск, обычный ярлык или EXE.
- Возврат того же окна после проверки пароля, без перезапуска приложения.
- Повторная блокировка после закрытия последнего окна приложения.
- Автоматическая SYSTEM-служба и отдельные фоновые защитники пользовательских сеансов.
- Проверка пароля в службе; PBKDF2-SHA256 и Windows DPAPI для хранения настроек.

## Требования и сборка

Windows 10/11 **x64**, .NET Framework 4.8, PowerShell. NuGet и сторонние библиотеки не требуются.

```powershell
.\build.ps1
```

Результат — `AppGate.exe` и `ServiceEdition\AppGateService.exe`. EXE, личные настройки, отчёты и временные данные тестов не хранятся в Git.

## Установка и использование

1. Запустите собранный `AppGate.exe`, подтвердите установку службы и задайте пароль.
2. Один раз включите правило нужного приложения в AppGate. Уже открытые окна также будут блокироваться.
3. Далее запускайте приложение обычным способом. Специальные ярлыки не нужны; окно настроек AppGate можно закрыть.

Для обновления существующей установки запустите **новую сборку из папки проекта**:

```powershell
.\AppGate.exe --update
```

Пароль и состояния правил сохраняются. Подробности установки, удаления, восстановления и тестов: [ServiceEdition/README.md](ServiceEdition/README.md).

## Важные ограничения

Это блокировка **окон**, а не запрет выполнения кода или шифрование файлов. До обнаружения окно может кратко появиться, процесс может работать в фоне. Администратор Windows может обойти защиту; при отключённом UAC административный Диспетчер задач также может завершать компоненты. Приложения с более высокими правами, чем у защитника, не поддерживаются.

Проверки выполнены на Windows 10. Работа с Codex подтверждена пользователем. Windows 11 и несколько пользовательских сеансов требуют отдельной проверки. Исполняемые файлы не подписаны сертификатом издателя.

Текущий код расположен в `ServiceEdition/`. Корневой `AppGate.cs` — сохранённый ранний прототип, не участвующий в сборке. Лицензия: [MIT](LICENSE).

## Запуск

1. Запустите AppGate.exe и создайте пароль (не менее 8 символов).
2. Выберите готовое правило Codex / ChatGPT или добавьте свой exe.
3. Сохраните работу в выбранном приложении, нажмите «Вкл. / выкл.». Включение закрывает запущенные процессы приложения принудительно.
4. Сверните AppGate в трей. При обнаружении запуска он закроет приложение и запросит пароль. Кнопка «Открыть» позволяет сначала ввести пароль, затем запустить приложение.
5. Разрешение действует на всю сессию приложения, включая дочерние процессы с тем же путём. Через 2 секунды после завершения всех процессов пароль требуется снова. После разрешения даётся 12 секунд на первоначальный запуск.

Настройки и выход через трей требуют пароль. Открытое окно настроек уже авторизовано: сверните его после настройки. Для автозагрузки создайте ярлык AppGate.exe в папке, открываемой Win+R → shell:startup. При запуске AppGate потребуется пароль; до его ввода мониторинг не работает. Автозагрузка автоматически не меняется.

## Ограничения

Это защита от случайного доступа внутри вашего профиля, не граница безопасности Windows. Программа опрашивает процессы каждые 350 мс: окно может кратко появиться, код приложения успевает начать работу. Принудительное закрытие может потерять несохранённые изменения. Процессы с повышенными правами могут оказаться недоступны — статус сообщит об ошибке закрытия, если процесс удалось обнаружить. Не используйте для системных процессов.

Блокировка не защищает файлы и историю на диске. Пользователь того же профиля может завершить AppGate или удалить его настройки. Пароль хранится в виде PBKDF2-SHA256 (210000 итераций, случайная соль), весь конфиг дополнительно защищён Windows DPAPI для текущего пользователя. DPAPI не защищает от программ, уже работающих от вашего имени.

Правило Store привязано к пакету OpenAI.Codex и издателю в имени каталога; после обновления номер версии может изменяться. Это сопоставление пути, не криптографическая проверка подписи. Beta-пакет и CLI не блокируются этим правилом. Обычные exe сопоставляются по полному пути, перенос или копия обходят правило.

Если забыли пароль: завершите AppGate через диспетчер задач и переименуйте %LOCALAPPDATA%\AppGate\settings.dat. Следующий запуск создаст новый профиль. Правила потребуется задать заново.

## Сборка и проверка

Запустите build.ps1 в PowerShell. Используется компилятор .NET Framework из Windows, NuGet не требуется.
AppGate.exe --self-test проверяет пароль, DPAPI, сопоставление пакета и закрытие отдельного тестового процесса. Результат: test-result.txt рядом с exe. Эта проверка не закрывает Codex.

Сборка предназначена для Windows 10/11 с .NET Framework 4.8. Фактическая проверка на Windows 11 должна выполняться отдельно. Исполняемый файл не подписан сертификатом издателя.
