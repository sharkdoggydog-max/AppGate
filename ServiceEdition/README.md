# AppGate 3 — блокировка окон

Текущая реализация — собственный бесплатный аналог поведения app-locker, не копия кода Cisdem. Windows 10/11 x64, .NET Framework 4.8. Проверено на этой Windows 10; Windows 11 и другие пользовательские сеансы пока не проверены на реальной системе.

## Использование

1. Обновление: `AppGateService.exe --update` с административными правами. Пароль и состояния правил сохраняются. Собственные старые IFEO-перехватчики снимаются. Специальные ярлыки, созданные предыдущей версией для текущего пользователя, перемещаются в `C:\ProgramData\AppGateService\legacy-shortcuts`.
2. В настройках AppGate один раз включите защиту нужного приложения. Уже открытые окна тоже попадут под блокировку.
3. Запускайте приложение обычным способом: Пуск, любой ярлык или EXE. Фоновый защитник скрывает окно и показывает пароль. Верный пароль возвращает то же окно без перезапуска приложения. После закрытия последнего окна пароль потребуется снова.
4. Отмена просит приложение закрыться обычным способом (WM_CLOSE), не убивая процесс. При наличии несохранённых данных приложение может остаться скрытым. Снятие правила в AppGate возвращает скрытые окна.

## Как работает и ограничения

- SYSTEM-служба хранит пароль (PBKDF2 + машинный DPAPI), проверяет запросы через локальный канал и запускает защитник в вошедших пользовательских сеансах.
- Защитник работает с токеном пользователя. Его объект процесса принадлежит SYSTEM: доступ к завершению не выдан обычным пользователям. Служба проверяет его раз в секунду и восстанавливает после завершения. Администратор намеренно сохраняет возможность аварийного восстановления.
- WinEventHook и резервный опрос окон скрывают защищённые окна через ShowWindowAsync. Метки на скрытых окнах позволяют новому защитнику восстановить состояние после перезапуска.
- **Это защита доступа к окнам, не запрет исполнения кода.** До обнаружения окно может кратко появиться. Процесс, фоновые операции и доступ к файлам не блокируются; файлы приложения не шифруются. Имя EXE можно обойти переименованием.
- Окна с более высоким уровнем прав, чем у защитника, не поддерживаются. Другие рабочие столы, консольные приложения и UWP-окна, принадлежащие процессу-контейнеру, не покрыты этой реализацией.
- Уничтожение/отключение службы администратором, безопасный режим и технические обходы не исключены. На машине с **UAC=0** административная учётная запись запускает и Диспетчер задач с полными правами — запрет его завершения здесь не обещается. Системные политики и Диспетчер задач AppGate автоматически не блокирует.
- Во время остановки/обновления службы есть перерыв в защите. Новые окна при недоступном защитнике не защищены. При потере связи работающий защитник сохраняет известные правила, но не выдаёт разрешение на ввод пароля.
- Запуск уже разблокированного приложения повторным нажатием ярлыка не требует нового пароля, пока его окна не закрыты.

## Проверки

- `--auth-test`: пароль, задержка после ошибок, смена и сохранение, отказ диска.
- `--window-test`: реальный отдельный EXE и WinForms-окно; неверный/верный пароль, сохранение процесса, повторный запуск, отмена, снятие правила.
- `--supervisor-test` (администратор): временная SYSTEM-служба с пустыми правилами; запуск защитника в текущем сеансе, проверка запрета PROCESS_TERMINATE под токеном без административной группы/привилегий, восстановление защитника, очистка службы.
- `--status`: записывает PID службы и состояния правил в status.txt рядом с EXE. Не записывает пароль.
- Старый `--integration-test` проверяет **только архивный IFEO-режим** и не является проверкой версии 3.

## Восстановление

`"C:\Program Files\AppGateService\AppGateService.exe" --recover` от администратора снимает правила и удаляет службу после подтверждения. При штатной остановке службы защитник возвращает скрытые окна. Файлы установки и настроек остаются. Обычное удаление: `--uninstall`, требуется пароль AppGate.

## Что известно о Cisdem

В [официальном руководстве](https://www.cisdem.com/resource/cisdem-appcrypt-windows-advanced-guide.html) указаны постоянная работа в фоне и автозапуск; отдельно признаётся обход через Task Manager/CMD/System Settings. Точный внутренний механизм не опубликован. Используемые здесь Windows API — наш выбор, не подтверждённые внутренности AppCrypt.

# Архив версии 2 — ниже не инструкция для текущей версии

## Версия 2.2: обычные ярлыки

Отдельный ярлык больше не требуется. Включите правило один раз в настройках и оставьте его включённым. IFEO вызывает окно пароля при новом внешнем запуске exe независимо от ярлыка. Разрешение сессии больше не пропускает пароль для нового внешнего запуска; служба сама проверяет родительский процесс клиента для дочерних запусков. Окно пароля отображается поверх остальных окон. При запуске сохраняются наследуемые дескрипторы, необходимые некоторым дочерним процессам Electron.

Активация уже открытого окна без создания процесса не перехватывается IFEO. Для такого сценария потребуется отдельная блокировка доступа к открытым окнам. Совместимость всех вариантов Store-активации не установлена. Раздел версии 2.1 ниже сохранён как описание предыдущего подхода; создавать отдельные ярлыки для новой версии не нужно.

## Версия 2.1: запуск с ярлыка

После установки или обновления появляются ярлыки **«Codex — с паролем»** на рабочем столе и в меню «Пуск». Нажатие показывает отдельное окно пароля поверх остальных окон. После правильного пароля AppGate включает правило, если оно было выключено, выдаёт разрешение для вашей сессии и запускает Codex. Заходить в настройки для ежедневной блокировки/разблокировки не нужно. Ярлык запрашивает пароль при каждом нажатии, даже если Codex уже работает; служебные дочерние запуски используют разрешение сессии.

Существующий пункт ChatGPT в меню Пуск не заменяется: пакетные ярлыки Microsoft Store могут обрабатывать запуск по-другому. Используйте новый пункт «Codex — с паролем», при желании закрепите его. Он находит актуальный путь через регистрацию пакета Windows, поэтому номер версии в ярлыке не зафиксирован.

Для обновления сохранённой установки запустите новую сборку с параметром `--update` (UAC). Пароль и правила сохраняются; служба кратковременно перезапускается, старая программа сохраняется рядом как `.backup-<дата>`. Текущий Codex не закрывается. Правило будет включено после успешного ввода пароля в новом ярлыке. Кнопка «Ярлык Codex с паролем» в настройках восстанавливает ярлыки для текущего пользователя.

Собственная бесплатная реализация блокировки приложений. Windows 10 и Windows 11 **x64**, .NET Framework 4.8. Это не продукт Cisdem; его код и оформление не используются.

## Чем отличается от первой версии

При обычном запуске защищённого exe Windows сначала открывает AppGate. AppGate проверяет пароль через службу, после чего запускает целевой процесс. Завершение окна настроек или окна пароля не снимает правило. При остановленной службе защищённое приложение через обычный запуск не открывается.

Используется IFEO Debugger, а не периодическое завершение процессов. Эта техника предназначена Windows для отладки. Она требует тестирования с конкретными приложениями и не является полноценной границей безопасности ОС.

## Установка

1. Запустите AppGateService.exe. Подтвердите UAC и установку службы, задайте пароль 10–256 символов.
2. Файлы устанавливаются в `C:\Program Files\AppGateService`, настройки — в `C:\ProgramData\AppGateService`. Служба `AppGateService` запускается автоматически от SYSTEM. Служба перезапускается Windows после аварийного завершения.
3. В настройках выберите Codex / ChatGPT и включите защиту. Это правило для **всех файлов ChatGPT.exe**, в том числе других версий и других продуктов с таким именем. Оно первоначально выключено.
4. Сохраните работу и полностью закройте защищаемое приложение, включая фоновые процессы. Уже запущенное приложение принудительно не закрывается.
5. Запустите защищаемое приложение обычным способом. Введите пароль. После закрытия всех процессов вашей сессии и двухсекундной паузы пароль снова требуется. На первоначальный запуск выделено 15 секунд.
6. Окно настроек можно закрыть. Значок в трее или пользовательский монитор не требуются: Windows открывает запрос при запуске exe.

Разрешение действует для одного пользователя в одной сессии Windows. Пароль настройки общий для всей машины. Для смены правил и пароля потребуется текущий пароль. Окно списка правил доступно без пароля, операции изменения защищены на стороне службы.

## Совместимость

Обычные Win32-приложения запускаются после разрешения через CreateProcess с DEBUG_ONLY_THIS_PROCESS и немедленным отключением отладчика. Аргументы запуска передаются, рабочий каталог сохраняется. Поведение программ с собственными отладчиками, античитами, повышением прав, специальными наследуемыми дескрипторами и механизмами Store-активации требует отдельной проверки.

**Совместимость с магазинным Codex / ChatGPT не подтверждена.** IFEO-перехват exe не гарантирует сохранение контекста активации MSIX. Если приложение не открывается после пароля, выключите правило в настройках. Не меняйте права папки WindowsApps и не отключайте защитные функции Windows.

## Границы защиты

AppGate не защищает от администратора Windows: он может удалить IFEO-правила, остановить службу и заменить файлы. Программист может обойти IFEO и без знания пароля, например используя отладочный запуск. Это защита от обычного запуска и простого завершения интерфейса, **не средство изоляции недоверенного пользователя**. Название exe можно изменить, а доступ к данным и истории на диске не блокируется. Уже открытые процессы не блокируются, блокировка экрана не отменяет разрешение для продолжающего работать приложения.

Пароль хранится как PBKDF2-SHA256 с индивидуальной солью, 210000 итераций, весь конфиг дополнительно защищён DPAPI LocalMachine и файловыми ACL SYSTEM/Administrators. Обычный пользователь не может прочитать или заменить настройки. После пяти неверных паролей для SID действует пауза 30 секунд. Администраторский доступ допускает восстановление без пароля приложения.

## Удаление и восстановление

«Удалить AppGate» в настройках или стандартный список приложений Windows: UAC, пароль AppGate, подтверждение. Снимаются собственные IFEO-правила и удаляется служба. Файлы и конфиг остаются для ручного удаления после закрытия программы.

Если служба не запускается или пароль утрачен, запустите **от имени администратора**:

```powershell
& 'C:\Program Files\AppGateService\AppGateService.exe' --recover
```

Это штатное аварийное снятие защиты без пароля AppGate, с подтверждением. Чужие IFEO-правила не снимаются. После восстановления можно удалить папки AppGateService в Program Files и ProgramData. Не удаляйте exe вручную, пока активны правила: они будут ссылаться на отсутствующий обработчик и мешать запуску защищённых приложений.

## Сборка и тест

`build.ps1` собирает x64 exe без NuGet и дополнительных библиотек. `AppGateService.exe --integration-test` требует администратора: создаёт уникальный тестовый exe, временное IFEO-правило только для него и временную службу AppGateTest_*. Проверяет отсутствие выполнения до разрешения, запуск после пароля, IPC, истечение разрешения, отказ при недоступном сервере и автоматическое восстановление реальной службы после принудительного завершения её процесса. Убирает свою службу и правило в finally. Итог — integration-result.txt. Тестовые файлы остаются рядом в папке test-* для диагностики; реальные приложения не блокируются.

Тест пройден на Windows 10, сборка 19044. Проверены запуск службы в сессии 0 и её восстановление. Интерактивный установщик, запуск пакета Microsoft Store и Windows 11 требуют отдельных проверок. Файл не подписан сертификатом издателя. Постоянная установка и включение защиты текущего Codex во время разработки не выполняются.
